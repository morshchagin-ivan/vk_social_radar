# Implementation Plan

Project: VK Social Radar

Version: 1.0

---

# Purpose

Документ описывает поэтапную реализацию проекта.

Каждый этап является самостоятельной инкрементальной поставкой (Increment), имеющей измеримый результат и критерии готовности.

План построен таким образом, чтобы после завершения каждого этапа система оставалась работоспособной и могла быть протестирована.

---

# Общая схема реализации

| Этап | Название | Основной результат |
|------|----------|--------------------|
| 1 | Foundation | Базовая инфраструктура проекта |
| 2 | Collector MVP | Сбор данных VK |
| 3 | Snapshot Engine | Хранение снимков |
| 4 | Backend API | REST API |
| 5 | Frontend MVP | Пользовательский интерфейс |
| 6 | Timeline | История изменений |
| 7 | Social Graph | Построение графа связей |
| 8 | Analytics Engine | Аналитика данных |
| 9 | AI Integration | AI Report и AI Chat |
|10 | Export & Search | Поиск и экспорт |
|11 | Stabilization | Оптимизация и тестирование |
|12 | Production Ready | Подготовка к релизу |

---

# Этап 1. Foundation

## Цель

Подготовить инфраструктуру проекта и базовую архитектуру.

## Основные работы

- структура каталогов;
- Backend;
- Frontend;
- SQLite;
- Playwright;
- базовая конфигурация;
- логирование;
- конфигурационные файлы.

## Ожидаемый результат

Работающий каркас приложения.

## Зависимости

Отсутствуют.

## Критерии завершения

- проект собирается;
- Backend запускается;
- Frontend запускается;
- Collector может быть запущен;
- база данных создаётся автоматически.

---

# Этап 2. Collector MVP

## Цель

Получить возможность собирать данные из VK.

## Основные работы

- запуск браузера;
- использование существующего профиля;
- получение списка друзей;
- получение диалогов;
- получение сообществ;
- нормализация данных.

## Ожидаемый результат

Collector успешно получает данные пользователя.

## Зависимости

Этап 1.

## Критерии завершения

- Collector успешно запускается;
- авторизация работает;
- данные извлекаются;
- отсутствуют необработанные ошибки.

---

# Этап 3. Snapshot Engine

## Цель

Создать механизм хранения неизменяемых Snapshot.

## Основные работы

- Snapshot Builder;
- модели данных;
- сохранение объектов;
- метаданные;
- связи между сущностями.

## Ожидаемый результат

Каждый запуск Collector создаёт новый Snapshot.

## Зависимости

Этапы 1–2.

## Критерии завершения

- Snapshot сохраняется;
- данные не дублируются;
- поддерживается несколько Snapshot;
- предыдущие Snapshot остаются неизменными.

---

# Этап 4. Backend API

## Цель

Реализовать единый REST API.

## Основные работы

- REST Endpoints;
- OpenAPI;
- сериализация;
- обработка ошибок;
- валидация.

## Ожидаемый результат

Frontend получает доступ ко всем функциям через Backend.

## Зависимости

Этап 3.

## Критерии завершения

- все основные endpoints работают;
- OpenAPI соответствует реализации;
- API проходит smoke-тестирование.

---

# Этап 5. Frontend MVP

## Цель

Предоставить пользовательский интерфейс.

## Основные работы

- Dashboard;
- список Snapshot;
- просмотр данных;
- запуск Collector.

## Ожидаемый результат

Пользователь способен работать с системой без обращения к консоли.

## Зависимости

Этап 4.

## Критерии завершения

- Frontend подключён к API;
- отображаются Snapshot;
- отображаются основные сущности;
- Collector запускается через UI.

---

Показать историю изменений между Snapshot.

## Основные работы

- вычисление изменений;
- Timeline Engine;
- API Timeline;
- визуализация.

## Ожидаемый результат

История изменений доступна пользователю.

## Зависимости

Этапы 3–5.

## Критерии завершения

- изменения вычисляются корректно;
- события сортируются по времени;
- поддерживаются фильтры.

---

## Цель

Вычислить производные аналитические показатели.

## Основные работы

- активность;
- связи;
- статистика;
- агрегированные показатели.

## Ожидаемый результат

Dashboard отображает аналитические данные.

## Зависимости

Этапы 6–7.

## Критерии завершения

---

# Этап 9. AI Integration

## Цель

Интегрировать локальную языковую модель.

## Основные работы

- AI Worker;
- RAG Service;
- AI Report;
- AI Chat.

## Ожидаемый результат

Пользователь получает интеллектуальный анализ данных.

## Зависимости

Этапы 6–8.

## Критерии завершения

- AI Report создаётся;
- AI Chat отвечает;

- контекст подготавливается через RAG.

- журналирование;

- подготовлены инструкции для эксплуатации.

# Definition of Done

Каждый этап считается завершённым только при выполнении следующих условий:

- реализован заявленный функционал;
- код проходит статический анализ;
- отсутствуют критические ошибки;
- обновлена архитектурная документация;
- актуализирована OpenAPI (при необходимости);
- добавлены автоматизированные тесты для новой функциональности;
- изменения успешно проходят smoke-тестирование;
- система остаётся полностью работоспособной после интеграции этапа.
