# 1. Vision

## Product Vision

VK Social Radar — локальная интеллектуальная система анализа социальной активности пользователя ВКонтакте.

Система предназначена для накопления, хранения, анализа и интерпретации социальной истории пользователя посредством периодического формирования снимков состояния (Snapshots), определения изменений между ними и предоставления аналитических выводов при помощи локальной языковой модели.

Все данные пользователя остаются исключительно на его компьютере.

---

## Business Goal

Предоставить пользователю инструмент для:

- анализа собственной социальной активности;
- понимания изменений окружения;
- восстановления истории отношений;
- поиска закономерностей общения;
- формирования персональной базы знаний;
- получения аналитических рекомендаций.

---

## Product Principles

- Local First
- Privacy First
- Snapshot First
- Explainable AI
- AI Native
- Extensible Architecture
- Offline by Design

# 4. Functional Requirements

# FR-1 Collector

Система должна выполнять сбор данных из VK.

## FR-1.1

Проверить наличие авторизованной пользовательской сессии.

## FR-1.2

При отсутствии авторизации завершить сбор с соответствующим сообщением.

## FR-1.3

Последовательно собрать все поддерживаемые сущности.

## FR-1.4

Зафиксировать ошибки сбора.

## FR-1.5

Создать журнал выполнения Collector.

---

# FR-2 Snapshot Engine

## Snapshot Definition

Snapshot представляет собой неизменяемый снимок состояния системы в конкретный момент времени.

Snapshot включает:

- друзей;
- подписчиков;
- подписки;
- диалоги;
- сообщества;
- каналы;
- свойства профилей;
- статистику сбора;
- технические метаданные.

Relationship Score, AI-анализ и граф не входят в Snapshot и вычисляются отдельно.

---

## Snapshot Lifecycle

Система должна поддерживать:

- создание;
- хранение;
- просмотр;
- экспорт;
- импорт;
- удаление.

---

# FR-3 Diff Engine

Diff выполняется между двумя выбранными Snapshot.

Если Snapshot явно не выбран, используется последний и предыдущий.

Определяются:

- новые объекты;
- удаленные объекты;
- изменения атрибутов;
- изменения активности.

---

# FR-4 Relationship Intelligence

Relationship Score рассчитывается после завершения Diff.

Алгоритм расчета определяется отдельной спецификацией.

Relationship Score является производной величиной и не хранится внутри Snapshot.

---

# FR-5 Timeline

Timeline строится по накопленной истории Snapshot.

Для каждого контакта отображаются:

- дата появления;
- начало общения;
- пики активности;
- периоды отсутствия активности;
- изменения профиля.

---

# FR-6 Social Graph

Graph строится по последнему Snapshot.

Тип графа определяется отдельной архитектурной спецификацией.

Поддерживаются:

- центральность;
- кластеры;
- сообщества;
- мосты.

---

# FR-7 Dashboard

Dashboard отображает данные исключительно последнего успешно созданного Snapshot.

Dashboard не обращается напрямую к VK.

После создания нового Snapshot Dashboard автоматически обновляется.

---

# FR-8 AI Pipeline

После завершения Snapshot выполняются:

1. Diff
2. Индексация
3. Формирование RAG
4. AI Analysis
5. Обновление Dashboard

---

# FR-9 AI Chat

AI Chat отвечает только по локальной базе данных.

Источник знаний:

- Snapshot;
- Diff;
- Timeline;
- AI Reports.

Запросы к Интернету отсутствуют.

---

# FR-10 Personal CRM

Система предоставляет:

- напоминания;
- список VIP;
- историю общения;
- давно неактивные контакты.

---

# FR-11 OSINT

OSINT является отдельным режимом.

Используются только открытые данные.

Приватные данные сторонних пользователей не анализируются.

# 7. Alternative Flows

## AF-1 Пользователь не авторизован

Collector завершается.

Snapshot не создается.

---

## AF-2 VK изменил DOM

Collector фиксирует ошибку.

Предыдущий Snapshot сохраняется.

---

## AF-3 LM Studio недоступен

Collector продолжает работу.

AI отключается.

---

## AF-4 Нет сети

Collector завершает выполнение с ошибкой.

Snapshot не создается.

---

## AF-5 Повреждение SQLite

Пользователь получает сообщение.

Сбор прекращается.

---

# 10. Assumptions

Предполагается, что:

- пользователь владеет аккаунтом VK;
- пользователь самостоятельно проходит авторизацию;
- Chromium содержит действующую сессию;
- локальная LLM установлена при использовании AI;
- пользователь имеет доступ к локальной файловой системе.

---

# 11. Acceptance Criteria

## Collector

- успешный сбор поддерживаемых сущностей;
- журнал выполнения сохранен;
- ошибки логируются.

---

## Snapshot

- Snapshot создается;
- Snapshot неизменяем;
- Snapshot можно экспортировать;
- Snapshot можно импортировать.

---

## Diff

- изменения корректно определяются между двумя Snapshot.

---

## Dashboard

- отображает только последний успешный Snapshot;
- автоматически обновляется после нового сбора.

---

## AI

При доступной локальной LLM:

- формируется индекс;
- выполняется анализ;
- доступны отчеты;
- AI Chat отвечает на вопросы по локальной базе.

При недоступной LLM остальные функции системы продолжают работать.

---

## Security

Подтверждается, что:

- данные не передаются третьим лицам;
- отсутствуют облачные запросы;
- пользователь может полностью удалить локальную базу.
